# Architecture Note — Phase 0/1 foundations (2026-11-18)

Decisions taken during implementation (supplements DECISIONS.md ADRs; ratify or amend at review):

1. **Test database without Docker daemon.** Package `@assetnest/db` runs migration + invariant tests against PGlite (real PostgreSQL 17 compiled to WASM). CI additionally applies the same migration chain against a `postgres:17` service container (`.github/workflows/ci.yml`). No test ever uses SQLite or mocks of PG semantics.
2. **Migrations.** drizzle-kit generates SQL from `packages/db/src/schema.ts`; one hand-written `0001_integrity_constraints.sql` adds check constraints + composite same-workspace FK for `locations.parent_id` (locations tree integrity beyond service-layer checks). Every migration ships with `--> statement-breakpoint` separators so it applies via both `node-postgres` and `pglite` migrators.
3. **Roles.** Built-in role catalog (`roles` keyed `owner|admin|manager|member|auditor`) seeded from `@assetnest/domain` `ROLE_PERMISSIONS` (single source of truth, mirrored to `role_permissions`). `roles.key` is globally unique; workspace-custom roles are deferred to P6 (fine-grained permissions) via a new additive migration — `workspace_id` column already reserved, built-ins use NULL.
4. **Ownership transfer is not implied by `workspace:manage`** — it is a distinct owner-only rule enforced at the service layer (admins manage users/roles but cannot transfer ownership).
5. **Asset optimistic concurrency** uses integer `version` with explicit `expectedVersion` on writes (409 `ASSET_VERSION_CONFLICT`), never last-write-wins. All lifecycle mutations append `asset_events` in the same transaction.
6. **IDs** are UUID v4 (`gen_random_uuid()`). Spec allows UUIDv7 or UUID; switch to v7 via a new `assetTag`-adjacent key or library if index locality matters at scale (not a Phase 1 concern).
7. **CSRF (final).** Browser sessions use SameSite=Lax cookies (primary defense) plus a synchronizer token: `csrfToken = base64url(HMAC_SHA256(SESSION_SECRET, sessionToken))`, returned by `/auth/login`, `/auth/register` and `/auth/me`. The SPA keeps it in memory only and sends it as `x-csrf-token` on every mutating request; the server recomputes the HMAC from the session cookie and compares in constant time. Stateless — no server-side CSRF state beyond the session itself; token survives page reloads and dies with session revocation/expiry. No localStorage, no double-submit cookie. API tokens (P4) will bypass CSRF (bearer header, not cookie).
8. **Tenancy path**: browser → generated client → Nest guard resolves `workspaceId` from route param → membership check on every request (deny-by-default) → service-layer scoping on every query (`workspaceId` predicate mandatory) → composite FKs where cross-workspace references are possible (locations tree). No tenant id accepted from request bodies.
9. **Amounts** `numeric(18,2)` as string end-to-end (drizzle default), ISO-4217 currency `char(3)` validated by check constraint.
10. **Custom migrations never edit 0000+**; additive only. Snapshot upgrade test (migrate previous release → current) deferred to P6-03 drills; fresh-chain test exists.

Open items for review: node-postgres `migrate()` uses the same journal as PGlite (verified: both applied 0000+0001 cleanly in this workspace). Decision 7 to be ratified when P1-01 lands.
